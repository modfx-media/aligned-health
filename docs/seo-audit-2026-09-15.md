## Executive summary

The new Next.js site is largely wired correctly. Google is still ranking leftover Squarespace and ASAP Chiro signals.

Live production has HTTPS, apex canonicals, unique titles, Open Graph, robots, and a 485-URL sitemap. Homepage on-page score is **97.1** when crawled over HTTPS. Organic for “chiropractor laguna hills” is about **#9** (absolute ~#13 under the map pack). The practice is **not in the map pack**. Third-party crawl data shows about **10 crawled pages vs 485 sitemap URLs**. Estimated organic traffic is ~**15 visits/month** across **38** ranking keywords, many of which are other “Aligned Health” brands or leftover ASAP queries.

The main technical problem is not “missing SEO fields.” Several fields look complete in the repo while Google ignores them, distrusts them, or reads the wrong entity from them.

## 2. Fields we are using that Google does not use

This is the core technical finding. Several SEO fields were added because they look complete in code, not because Google uses them.

### Sitemap (`app/sitemap.ts`)

| Field | Why it was added | What Google does | Auditor action |
|---|---|---|---|
| `changefreq` | Sitemap 0.9 spec / Next `MetadataRoute` defaults | Ignored since ~2020 | **Remove** |
| `priority` (1.0 down to 0.3) | To “rank” hub pages above city combos | Ignored; does not choose crawl order | **Remove.** Internal links decide crawl priority |
| `lastmod` = `new Date()` on every static URL | To look freshly updated | Used only if it matches a real content change. Stamping every URL as “today” trains Google to ignore lastmod | Keep **only** for blog posts from real `dateModified`. Drop the fake stamp on static pages |

### Metadata

| Field | Where | What Google does | Auditor action |
|---|---|---|---|
| HTML `keywords` meta | Services, city×service pages, blog, Ranked posts | Ignored since 2009. Can still leak targeting to anyone who view-sources | Stop exporting `keywords` in `Metadata`. Keep arrays as internal notes if needed |

### JSON-LD

| Field | Where | Problem | Auditor action |
|---|---|---|---|
| `ClinicJsonLd.url` overwritten to `pagePath` | Every route that mounts `ClinicJsonLd` | Same `@id` (`https://alignedhealthoc.com#clinic`) with a **different `url` on every page**. Confirmed live on `/services/chiropractic-adjustments`: `@id` is the clinic, `url` is the service path | Lock clinic `url` to the homepage. Use WebPage / Service nodes for the page URL |
| `availableService` → `MedicalIndication` | Service JSON-LD | `availableService` belongs on a MedicalOrganization; values should be procedures/services, not `MedicalIndication`. Invalid pairing | Use `indication` on `MedicalTherapy`, or a `Service` node with `provider` + `areaServed` |
| `datePublishedText` | BlogPosting | Not a schema.org property | **Delete.** Keep ISO `datePublished` / `dateModified` |
| `keywords` as a comma-separated string | Blog collection + posts | Low value; stuffed CSV is not useful | Omit, or pass a short array of real topics |
| `areaServed` = one City, then overridden per city page | `ClinicJsonLd` | Mutates the **same clinic entity** so Irvine pages claim the clinic `url` is the Irvine path and `areaServed` is only Irvine | Keep clinic `areaServed` as a list of cities on the homepage entity only |

### Schema that is missing (these *are* worth adding)

On the clinic entity, live HTML is missing:

- `openingHoursSpecification` (hours were not found in site constants)
- `logo`
- Organization `sameAs` (Google Business Profile, Facebook, etc.)
- `Physician` / `Person` nodes for Dr. Dustin Hack and Dr. Tara Hadden (`alumniOf`, credentials, `knowsAbout`)
- Honest `aggregateRating` **only** if it comes from live Google totals — do not stamp a fake rating

BreadcrumbList is on city/combo pages only. Missing on home, about, team, contact, and the services hub.
